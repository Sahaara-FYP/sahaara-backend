1. INTRODUCTION AND SYSTEM OVERVIEW
-------------------------------------------------------------------------------

Sahaara is a smart, real-time backend built for hyperlocal community support. The system works as a digital connection within neighborhoods, letting residents post help requests for medical aid, food, or safety. Nearby members can respond with resources or specific physical services. The backend manages real-time location matching, trust-based rating systems, and secure identity verification to maintain a reliable community environment.

2. REVERSE ENGINEERING ANALYSIS
-------------------------------------------------------------------------------

2.1 Folder Structure
The repository uses a module-based structure where features are grouped but lack strict layer separation.

sahaara-backend/

5. SYSTEM WEAKNESS IDENTIFICATION
-------------------------------------------------------------------------------

5.1 Architectural Coupling
Location: src/modules/requests/requests.ts
The business logic is mixed within the Express route handlers. Database transactions and matching algorithms are combined with HTTP response logic. This prevents testing the matching engine by itself.

5.2 Inconsistent Validation
Location: src/modules/alerts/alerts.ts (Line 45)
Input checking is done manually using basic "if" statements. This is brittle. If a check is missed for one field, it can cause errors in the database layer.

5.3 Standard Error Handling Issues
Location: Project-wide
Errors are handled via generic catch blocks that return a 500 status code with a standard message. This hides system diagnostics and makes debugging harder for frontend developers.

5.4 Database Dependency (Raw SQL)
Location: src/modules/requests/requests.ts (Line 326)
The system uses raw SQL strings for geographic distance calculations. This creates a hard dependency on Postgres syntax, which makes database migration or scaling more difficult.

6. RE-ENGINEERING PROPOSAL
-------------------------------------------------------------------------------

6.1 Architectural Transformation: Service-Repository Pattern
The proposal is a shift to a three-tier architecture:
1. Controller Layer: Handles HTTP parsing and status codes only.
2. Service Layer: Contains the pure business logic and algorithms.
3. Repository Layer: Manages database calls and removes raw SQL from the logic.

6.2 Technical Transformation Snippets

Example A: Validation Modernization
Current (Manual Checks in alerts.ts):
if (!title) {
  return res.status(400).json({ error: "Title is required" });
}
if (!locationLat || !locationLng) {
  return res.status(400).json({ error: "Location is required" });
}

Improved (Schema-Based Validation via Zod):
const AlertSchema = z.object({
  title: z.string().min(1),
  locationLat: z.number(),
  locationLng: z.number(),
});
const validated = AlertSchema.parse(req.body);

Example B: Architectural Decoupling
Current (Logic in Controller):
requestsRouter.post("/", async (req, res) => {
  const request = await prisma.request.create({ data: req.body });
  await smartMatchRequest(request.id);
  res.status(201).json(request);
});

Improved (Service Layer Delegation):
requestsRouter.post("/", async (req, res) => {
  const newRequest = await RequestService.createNewHelp(req.userId, req.body);
  return res.status(201).json(newRequest);
});

7. TRACEABILITY MATRIX
-------------------------------------------------------------------------------

Weakness: Architectural Coupling
Re-Engineering Solution: Service-Repository Pattern
Impact: Logic becomes testable on its own.

Weakness: Inconsistent Validation
Re-Engineering Solution: Zod Schema Middleware
Impact: Full type-safety for all API inputs.

Weakness: Error Inconsistency
Re-Engineering Solution: Global Error Handler Middleware
Impact: Standardized API responses across the app.

Weakness: Raw SQL Dependency
Re-Engineering Solution: Repository Abstraction Layer
Impact: Decouples logic from the database type.

-------------------------------------------------------------------------------
8. CONCLUSION
-------------------------------------------------------------------------------

The Sahaara backend is a functionally rich platform currently using a "Fat Route" architecture with high cognitive complexity. By moving to the Service-Repository pattern and standardizing validation, the system will achieve the modularity needed to transition from a prototype to a production-grade community engine.
